# Astra — Market Lead Engine

Отдельная версия Market Lead Engine: Bybit microstructure, проверяемые сигналы, real-time график и журнал виртуальных сделок. Интерфейс помечен **ASTRA-001**.

Основа сохранена из `hobbit7771/elliott-wave-analyzer`, ветка `claude/t3-elliott-wave-engine-gw2gm1`, commit `03182b433eebe3444a49ca7d967e7090c936a2af`. Изменения публикуются только в этом отдельном репозитории. Описание исходного проекта сохранено в [docs/LEGACY_README.md](docs/LEGACY_README.md).

## Запуск Astra

`render.yaml` запускает `astra_app:app`, включает `LEAD_ENGINE_ENABLED=true` и создаёт отдельный сервис `astra-market-lead-engine`. Старый Analysis/AI dashboard при этом не запускается. Для API биржи достаточно публичного потока Bybit: ключи биржи и AI API не нужны.

Для локального запуска:

```sh
python -m venv .venv
.venv/bin/pip install -r requirements.txt
LEAD_ENGINE_ENABLED=true .venv/bin/uvicorn astra_app:app --host 0.0.0.0 --port 8000
```

Страницы:

- `/` — рынки, состояние потока и сигналы.
- `/lead-engine/INJUSDT` — график выбранной отслеживаемой пары, EMA, Fib и панель сигналов.
- `/paper` — результаты виртуальных сделок, комиссии и экспорт снимка журнала.
- `/api/lead-engine/status` — свежесть и состояние потоков. `/api/health` проверяет доступность приложения, а не качество рыночных данных.

## Как считается результат сделок

**PAPER — симуляция.** Ордеров на биржу приложение не отправляет. Вход производится по следующему доступному свежему стакану после сигнала, с учётом объёма по уровням. Вход по уже известной цене сигнала запрещён. Повтор одного сигнала не открывает дубликат позиции.

Начальные настройки: капитал 10 000 USDT, объём около 100 USDT на сделку без плеча, комиссия 0,055% за каждую сторону, дополнительное проскальзывание 1 bps, стоп 0,5%, цель 1,5R, максимальный срок 15 минут, одна позиция на монету. Это допущения симуляции, а не проверенные тарифы аккаунта. Параметры задаются через `ASTRA_PAPER_*`; полный список — в `PaperConfig`.

Чистый P&L = направленное изменение цены × количество − комиссия входа − комиссия выхода. Открытый P&L учитывает предполагаемую стоимость закрытия. **Funding пока не учитывается.** При пропуске данных P&L не выдумывается: оценка скрывается, сделка помечается GAP, выход происходит по следующей доступной цене. Результаты не являются доказательством будущей прибыльности.

Журнал записывается в отдельный SQLite (`ASTRA_PAPER_DB`, по умолчанию `astra-data/paper.sqlite3`) и восстанавливает позиции/итоги при перезапуске с тем же файлом. **На Render Free локальный файл не переживает замену экземпляра/деплой.** Экспорт API содержит итоги и последние 50 закрытых сделок; полная история остаётся в таблице SQLite до потери диска. Для постоянного хранения нужен persistent disk на поддерживаемом тарифе и путь `ASTRA_PAPER_DB` на этот диск. Старый `T3_DATABASE_URL` этим журналом не управляет.

## Проверки и ограничения

Карта исходного кода: [CURRENT_ARCHITECTURE.md](CURRENT_ARCHITECTURE.md). Все изменения, результаты тестов, измерения и незакрытые пункты приёмки: [ASTRA_CHANGELOG.md](ASTRA_CHANGELOG.md).

Данные проходят проверку свежести, синхронизации стакана и очереди. На плохом потоке сигналы отключаются. Pressure отображается как **MODEL SCORE**; оценка probability допускается только по накопленным наблюдениям, её надёжная историческая валидация ещё не выполнена.

График использует Lightweight Charts 4.1.3, историю Bybit REST и реальные OHLC/volume/confirm из Bybit kline WebSocket. EMA обновляются локально, Fib хранится отдельно по паре и TF. Доступность Bybit и CDN библиотеки необходима на стороне сервера/браузера.

Полная live-приёмка ещё открыта: соединение Bybit из среды проверки не установилось, 30 минут live не пройдены. Ускоренный replay, автоматическая проверка JS и проверка на настоящем iPhone — разные виды доказательств; в отчёте они разделены.
